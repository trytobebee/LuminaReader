01

架构总览

Architecture · 以代码现状为准

LuminaReader 将阅读界面、文档数据与问答执行分开管理。当前问答入口使用统一执行循环：模型安排下一步，程序执行有明确输入输出的工具；已有答案、证据和流程可以复用。

本文说明 reader-tools-v1 的实现快照，供开发与后续设计融合使用。Harness 在这里指包在模型外面的执行代码：它管理上下文、工具、状态、缓存、预算和停止条件。

图 1 · 代码分层。模型决策通过执行器调用适配层；原文工具中的 extract 也会调用模型。
层次代码入口职责
界面src/main.js / src/style.css讨论与参考阅读、原文引用、Markdown 表格、执行过程和费用展示。
服务接口src/api/app.py / documents.py校验请求、选择文档数据库、提交任务、查询进度、接收反馈。
任务运行chat_runtime.py按文档隔离任务，检查答案缓存，后台排队执行和恢复。
执行核心reader_harness.py维护目标、证据和计划，执行动作、检查引用与覆盖情况。
工具与复用reader_tools.py / reader_workflows.py读取原文、抽取和统计；积累、选择及执行可复用步骤。
模型与用量model_client.py / usage.py适配模型服务，记录实际返回的 Token，用请求上限与费用预留约束执行。
原有数据继续使用：章节原文、约 150 字摘要、核心情节和人物索引仍在文档 SQLite 中。摘要负责定位线索，最终事实应回到原文确认。
02

问答 harness：一次请求的完整过程

Execution loop · 本文重点

当前入口没有“恰好两个名字就分析关系”的路由，也不要求先把问题归入固定类别。所有问题由 POST /api/chat 进入同一任务运行层。

图可横向滚动
图 2 · 入口旁路、核心循环与退出。答案缓存和已有任务不新建循环；流程复用从执行节点进入，省去初始规划。LLM 可直接提出答案或澄清，未通过引用或覆盖检查时返回补查。
步骤实际动作调用模型？
1. 接收上下文校验问题与范围；携带文档、最近 4 条对话（每条最多 1,500 字符）、当前章节和上一段范围。问题最多取 2,000 字符。否
2. 检查答案缓存根据问题、上下文、文档版本、模型及执行器版本定位任务；完整答案且关联流程未停用时直接返回。命中时为 0 次
3. 恢复或匹配流程恢复相同任务的检查点；新任务若有唯一、有效的启用模板，直接执行已保存步骤。恢复与匹配本身不调用
4. 决定下一步将目标、已获证据、执行结果、剩余额度和可用工具传给模型。模型可选择执行、回答或澄清。是
5. 执行工具解析结果引用，校验参数并查工具缓存。每次决策可提出 1–4 个工具调用，程序按顺序执行。只有未命中缓存的 extract 额外调用
6. 更新状态记录原文、字段记录、章节覆盖与用量，再交给模型判断是否补查。状态更新不调用
7. 完成或停止校验最终引用和覆盖要求，返回答案、出处、过程及用量；预算耗尽或重复无进展时保留检查点。整理答案属于模型决策；没有固定追加审稿调用

动作协议：由模型生成，由程序解释执行

{
  "goal": "比较两人的明确境界及时间条件",
  "plan": ["检索境界描述", "读取原文后比较"],
  "coverage": "targeted",
  "required_chapter_ids": [],
  "context_dependencies": [],
  "action": "execute",
  "calls": [
    {"id": "find", "tool": "search",
     "arguments": {"query": "秦宇 聂明升 境界"}},
    {"id": "read", "tool": "read",
     "arguments": {"chapter_ids": "$find.chapter_ids"}}
  ],
  "answer": "",
  "citations": [],
  "unresolved": []
}

$find.chapter_ids 表示使用前一步返回的章节 ID。action 可为 execute、answer 或 clarify。模型输出 JSON，由 Python 执行器解释；当前不运行模型生成的任意 Python 或 SQL。

示例的性质：上面的动作仅用于说明协议，不是一次实际付费请求的日志。两个名字只参与检索参数，不决定执行流程。

03

工具职责与 LLM 调用边界

Tools · 检索、证据与计算分开

工具是可以组合的能力，不是问题类别。一次问题可以多次调用同一个工具，也可以只读取少量原文后直接回答。

工具输入与输出调用 LLM实际约束
catalog按范围、分页浏览章节标题及摘要线索。否默认每页 40 章，最多 80 章。摘要是线索。
search关键词与范围 → 候选章节 ID。支持原文检索或索引检索。否当前按短语和二字词组匹配打分；不是向量检索。候选命中不算已读完。
read章节 ID、可选词组、分页位置 → 原文段落及稳定引用 ID。否默认每页最多 12,000 字符，上限 20,000；长单段可切成稳定小段。
scan起止顺序、词组、分页位置 → 全范围的匹配原文及前后文。否逐章检查，包括未命中章节；分页未结束时不能冒充匹配原文已全部读取。
extract已读段落 ID、字段名、抽取标准 → 带字段值和证据 ID 的记录，字段值以字符串保存。是，缓存命中则不调用最多 10 个字段；引用必须属于本次提供的原文。
aggregate已抽取记录、过滤条件、去重字段 → 计数或排序结果。否只接受已记录的抽取结果；重复键的字段冲突会要求核对，不能直接编造统计输入。
workflow已启用流程 ID、参数绑定 → 一组已记录的工具调用。执行器本身不调用内部含 extract 或后续生成时仍会调用模型。
扫描不消耗 Token：读取数据库、匹配关键词、切分段落和计算计数都是本地 Python 操作。只有把资料发送给模型规划、抽取或生成时，才产生模型 API 用量。

证据怎样跟随计算结果

原文段落保留 chapter_index、标题和文本，引用形如 c1787p40。抽取记录携带 evidence_ids；合并与统计保留这些出处。最终回答的引用从本轮证据集合中取出，界面可展开原文并跳回章节。

章节编号：工具参数使用原稿顺序 chapter_index。书中标题“第 N 章”可能重复或跳号，不能直接把标题章号当作数据库顺序。
04

动态计划与固定流程怎样融合

Reusable workflows · 复用步骤，不套用旧答案

新问题由模型动态安排工具调用；相似任务可复用已经积累的固定步骤。当前保存的流程是工具调用序列、参数和前后依赖，不是旧答案模板。

图 3 · 流程的积累与复用。启用检查主要验证结构、绑定和引用，不构成独立的事实正确性审查。

4.1 什么时候保存候选流程

仅当动态执行完成、引用有效、没有未决事项且过程中没有记录错误时，才尝试学习。步骤必须可由现有工具重放。调用 ID 会统一命名，避免两个同构步骤因为临时命名不同而分成两个流程。

当前自动参数化主要面向已入库姓名，最多 6 个。保留问题其余措辞，用 {{entity_0}} 等占位符绑定人物；读取、抽取和统计所需的来源必须由前面工具结果推导。复制了旧章节或段落 ID 的流程不能直接泛化到新人物。

4.2 什么时候省去规划调用

条件执行方式仍需做什么
唯一的启用模板与问题匹配校验姓名、模型版本、上下文和必要的原文版本后，直接执行步骤。使用当前原文，最后由模型生成答案或判断缺口。
问法变化，或不能唯一匹配向模型提供相关启用流程建议，由模型选择流程工具或继续动态执行。不能仅凭名字或相似词自动触发整套流程。
复用步骤执行出错或需要新增动作保留已取得的证据，回到动态补查，模式显示为 workflow_fallback。补查仍受同一任务的预算约束。

4.3 启用、上下文与负反馈

同一流程在两组不同姓名取值下通过执行与引用检查后，候选流程可启用；存在关联候选流程时，用户点击“有帮助”也可启用。无明确独立性声明的流程保留对话、章节和范围的上下文约束；存在固定来源 ID 的流程还绑定原文版本。

用户点击“有错误”会停用关联流程，停止相应答案缓存复用，并清理该次任务的模型抽取缓存。原始章节不会因此删除。停用状态不会因为后续自动积累样本而自行解除。

当前能力范围：流程库积累的是已有工具的组合；没有自动编写新底层工具函数，也没有将模拟测试轨迹导入正式流程库。
05

上下文、任务状态与三层缓存

State & cache · 让已完成的工作可以继续使用

讨论历史帮助理解追问，不能作为原文证据。执行器保存目标、计划、上下文依赖、工具结果、原文、覆盖进度、待执行动作和累计用量。模型每次接收受长度约束的状态视图，完整状态保存在本地。

缓存层匹配或失效依据对模型调用的影响
完成答案问题、最近历史、当前章节、范围、文档内容版本、模型身份与执行器版本。关联流程停用后不再复用。命中后本轮 API 次数为 0；保留原生成用量供查看。
工具结果工具名、已解析参数、文档版本、模型身份和工具版本。纯本地工具免重复计算；extract 命中时可免抽取调用。
可复用流程任务模板、参数绑定、上下文依赖、模型与工具版本；固定来源还检查文档版本。减少选择和安排中间步骤的调用；通常仍需最终生成。

文档隔离与磁盘结构

文档数据库所在目录/
└── reader_harness/
    └── <文档路径哈希>/
        ├── workflows.sqlite3          # 流程与工具结果缓存
        ├── <job_id>.json              # 本轮结果、出处、用量与过程
        ├── <job_id>.checkpoint.json   # 尚需恢复的执行状态
        └── <job_id>.feedback.json     # 反馈记录

文档版本根据章节原文、标题、摘要、情节及人物索引计算。数据变更后，旧答案与工具结果不再命中同一个内容版本。后台线程池当前一次执行一个问答任务。

恢复与重发：中断后的相同任务可加载检查点，已经完成的工具不必重做。恢复保留累计用量；预算耗尽后，单纯重发相同任务不会自动获得新的预算，需要调整预算或缩小问题范围。
06

费用预算、停止条件与证据约束

Execution limits · 以代码默认值说明

以下是 Limits 的代码默认值，运行时可由 LUMINA_CHAT_* 环境变量覆盖。模型每一步看到剩余调用次数；执行器在底层请求前检查限制，网络重试也计入物理请求次数。

配置默认值含义
MAX_CALLS8 次本轮物理模型请求上限，包含网络重试与 extract。
MAX_DECISIONS8 轮动态决策及最终回答轮数。
MAX_STEPS24 步成功执行的工具步骤上限，包括选择 workflow 的步骤记录。
MAX_SOURCE_CHARS180,000 字符本轮去重后加载的原文字符数预算。
MAX_INPUT_CHARS60,000 字符单次模型调用序列化输入上限，不是 Token 数。
MAX_OUTPUT_TOKENS5,000 Token单次输出上限，OpenAI Responses 的推理 Token 也包含在内。
MAX_COST_USD$0.50已知 GPT-6.1 Sol 定价下的保守预留额度；自托管 Qwen 费用仍未折算。

费用控制在请求前按输入字节数、输出上限和额外格式余量预留额度；收到有效用量后按返回记录结算。未取得有效计价用量的请求保留预留额。界面费用是估算，以服务账单为准。

何时停止或要求补充

  • 范围不明且影响结论：模型可返回澄清问题。
  • 引用不存在：执行器拒绝该答案，要求重新决策。
  • 全书或范围任务未覆盖要求章节：补查，或在 unresolved 中明确未完成事项。
  • 连续 3 次重复工具结果且没有新增结果，或达到预算/轮数限制：停止并保存进度。
覆盖检查的边界：执行器区分“按关键词逐章检索”和“完整读取章节”。已扫描每章只证明执行过指定词组检索，仍可能遗漏别名、代词和间接情节；引用存在也不证明它必然支持结论。
状态含义：后台任务的 status=completed 表示本轮执行返回，结果仍可能为部分回答或预算停止。应结合下一节的 harness.outcome 判断答案是否完成。
07

接口、界面与代码修改入口

Integration · 便于主对话继续融合设计
接口用途返回重点
POST /api/chat提交问题与上下文。运行中返回 202 和 job_id；答案缓存命中时返回已完成结果。
GET /api/chat/jobs/<id>轮询后台任务。阶段进度、最终 response、timeline、usage 与 harness。
GET /api/harness/workflows查看流程库。candidate / active / disabled、模板、步骤、样本数和命中次数。
POST /api/chat/feedback提交回答反馈。参数为 job_id 与布尔 helpful；用于启用或停用流程及处理相关缓存。
GET /api/model查看服务标识。模型、提供方和 harness 版本。

界面展示哪些信息

前端显示动态规划、读取、抽取、统计及复用阶段；回答下方可展开处理步骤，查看缓存命中、原文出处、API 次数与输入/输出 Token。返回结果也保存到当前讨论，便于切换后恢复。

字段当前值读者应如何理解
harness.modedynamic / workflow / workflow_fallback分别是动态执行、流程复用、复用后动态补查。
harness.outcomeanswered / partial / clarification / budget_exhausted分别是有据回答、存在未决事项、澄清问题、预算或无进展停止。
usageAPI 次数、Token、推理 Token、缓存 Token、估算费用是本轮各步骤汇总；未返回完整用量时会标记统计不完整。

验证记录、当前边界与阅读建议

Verification · 不把离线通过当作模型效果证明

以下记录来自本轮实现交接，本文生成没有重新执行 Reader 问答测试，也没有调用付费模型。

验证项目已记录结果能够说明什么
Python 离线回归61 项通过；模型响应均为模拟值。覆盖动态补查、流程学习、复用、缓存失效、文档隔离、反馈、预算与恢复等执行行为。
前端构建及模拟联调构建通过；桌面与手机模拟接口联调通过。检查阶段显示、过程、缓存标记、反馈和讨论恢复；没有真实模型调用。
真实小说的工具扫描原稿顺序 1738–1841，共 104 章；7 页、2,397 段、138,795 原文字符；模型请求 0 次。验证本地扫描分页、范围覆盖和原文定位；没有验证模型理解了这些章节。
真实模型验收已有用户发起的真实调用记录；尚未进行逐项事实验收。规划是否合理、抽取和答案是否准确，需要实际使用时评估。
流程启用不是事实保证：两个不同参数样本通过结构和引用检查，只是当前启用条件。它没有独立证明每条陈述都正确。负反馈可以停止继续复用，仍需结合真实问题检查效果。

当前实现仍有的边界

  • search 仍以关键词和二字词组匹配为主，未接入向量召回。
